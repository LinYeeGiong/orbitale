# Orbitale v0.2.0 Release Design

## Goal

Turn the current Orbitale preview into a reusable GitHub Template theme with a clear separation between reusable theme code and each author's personal content. Version 0.2.0 includes an MIT code license, one typed customization entry point, permanent pages for every published content type, a combined summary RSS feed, working tag archives, and release-quality documentation with real screenshots.

## Repository Model

Orbitale uses two repositories with different ownership boundaries:

- `LinYeeGiong/orbitale` is the public upstream theme and GitHub Template. It contains reusable code, sample content, documentation, screenshots, and tagged releases.
- `LinYeeGiong/LinYeeGiong.github.io` is Lin's personal site created from the template. It contains the real configuration, published articles, personal images, and the GitHub Pages deployment history.

The personal repository may add the theme repository as an `upstream` remote. Obsidian and OpenClaw publish only to the personal repository. Theme releases never contain Lin's private notes or draft inbox.

This release remains a template repository rather than an npm package. A package would require a stable component API and migration tooling that are outside the v0.2.0 scope.

## Theme Configuration

`src/config/site.ts` is the single user-editable customization entry point. It exports one typed `siteConfig` object containing:

- Identity: `name`, `shortName`, `title`, `description`, and introductory copy.
- Site metadata: `siteUrl`, `locale`, and `timezone`.
- Profile: `location`, GitHub URL, repository URL, and optional email.
- Navigation: labels and internal destinations.
- Terminal identity: user, host, shell title, placeholder, welcome copy, and shortcut commands.
- Exploration fields: stable ID, short label, title, description, destination, and matching content tags.
- Footer: copyright label, location label, and external links.

Components consume the config instead of embedding `Lin`, `LIN`, `Shanghai`, GitHub placeholders, terminal identity, or exploration copy. Interface labels that describe theme behavior remain in the components; only personal and theme-instance information moves into configuration.

Exploration counts and latest-entry titles are derived from published content whose tags match each configured field. They are not manually entered in configuration. A field with no matching entries displays zero and a neutral latest-entry message.

## Content URLs And Shared Data

All published Chinese entries receive permanent URLs based on Astro collection IDs:

```text
/notes/<id>/
/essays/<id>/
/daily/<id>/
```

Shared content utilities provide:

- Published Chinese collection filtering.
- Newest-first sorting.
- A canonical URL builder for every collection type.
- Previous and next entries within the same collection.
- A combined feed list across notes, essays, and daily entries.

Draft or non-Chinese entries do not produce v0.2.0 routes. Optional English routing remains a later milestone.

## Article Pages

Three thin dynamic route files use Astro `getStaticPaths()` and `render()`:

```text
src/pages/notes/[...slug].astro
src/pages/essays/[...slug].astro
src/pages/daily/[...slug].astro
```

They pass entries to one shared `ArticleLayout`. The layout renders:

- Content type, publication date, title, and description.
- Markdown or MDX body content.
- Tags and optional note or Daily metadata.
- A return link to the owning collection.
- Previous and next entries from that collection.
- A copy-link sharing control with a no-JavaScript canonical-link fallback.
- Canonical metadata, Open Graph article metadata, and `BlogPosting` JSON-LD.

List-page titles and descriptions link to their detail routes. Daily timeline entries also link to their permanent pages while preserving the timeline presentation.

Article typography follows Orbitale's existing serif and monospaced system. It supports headings, paragraphs, lists, links, blockquotes, inline code, fenced code, tables, figures, and responsive images. It does not add a new UI framework or syntax-highlighting dependency in this release.

## Tags

The existing homepage tag constellation already points to `/tags/<tag>/`. Version 0.2.0 adds a static tag route so those links do not return 404:

```text
src/pages/tags/[tag].astro
```

Each tag page combines matching published notes, essays, and Daily entries, sorts them newest first, and links to their permanent pages. Tag path encoding and lookup use the same shared content utility as the homepage.

## RSS

Astro's official `@astrojs/rss` package generates `/rss.xml`. The feed combines all three published Chinese collections and sorts them newest first.

Each item contains:

- Title and frontmatter description.
- Publication date.
- Content type label.
- Permanent detail-page link.

The feed uses summary content rather than rendered article bodies. This matches the lower-dependency approach used by AstroPaper and Astro Cactus, avoids HTML sanitization dependencies, and keeps image and relative-link handling deterministic. Feed title, description, language, and site URL come from `siteConfig` and Astro's configured `site` value.

## Licensing

The repository root receives the standard MIT License with copyright attributed to Lin and the current year.

MIT covers the Orbitale theme code. README states that, unless an author explicitly chooses another license, articles, notes, Daily posts, avatars, and personal media are copyright of their respective authors and are not licensed under Orbitale's MIT License. Sample content is clearly identified as demonstration material that template users should replace.

## README And Screenshots

README becomes the release guide and includes:

- Theme summary, feature list, requirements, and live-build commands.
- Three real screenshots: desktop homepage, mobile homepage, and article page.
- `Use this template` instructions.
- The two-repository model and exact personal repository naming for a root GitHub Pages site.
- A complete `siteConfig` customization guide.
- Content directories and frontmatter examples for all three collections.
- Local development, verification, and GitHub Actions deployment.
- How to add the theme repository as `upstream` and evaluate tagged updates.
- The code-versus-content copyright boundary.

Screenshots are committed as:

```text
docs/images/orbitale-home-desktop.png
docs/images/orbitale-home-mobile.png
docs/images/orbitale-post.png
```

They must be captured from the running implementation after v0.2.0 pages are complete. Desktop capture targets 1440px width, mobile capture targets 390px width, and the article capture must show actual rendered sample content. Generated or simulated UI images do not satisfy this requirement.

## Package And Release Metadata

`package.json` advances to `0.2.0` and adds a description, MIT license identifier, repository URL, homepage, and theme-related keywords. `@astrojs/rss` is a runtime dependency. No additional runtime framework is introduced.

The release commit is tagged `v0.2.0` only after verification and screenshots are complete. Creating the GitHub repository, enabling its Template setting, pushing, and creating the GitHub Release are external publication actions and require explicit user authorization at execution time.

## Failure And Empty States

- Collections with no published entries render their existing empty list structure without generating invalid detail pages.
- Exploration fields with no matches display count zero.
- Missing optional metadata is omitted rather than replaced with invented values.
- RSS generation requires a valid `site` URL and fails the production build when it cannot construct absolute item URLs.
- Copy-link failure leaves the visible canonical link usable and does not hide article content.

## Testing And Verification

- Unit tests cover content URL generation, combined sorting, field-tag aggregation, and previous/next selection.
- Astro rendering tests cover each collection's detail page, article metadata, list links, tag archive output, configuration-driven identity, and RSS items.
- Existing orbit, terminal, activity, route, and homepage tests remain green.
- `astro check` must report zero diagnostics.
- `astro build` must generate all list, detail, tag, and RSS routes.
- Browser checks cover desktop homepage, mobile homepage, article typography, tooltip interaction, internal navigation, and absence of overlap before screenshots are saved.
- `git diff --check` and a clean post-commit worktree complete verification.

## Reference Implementations

The design follows established patterns without copying their visual systems:

- AstroPaper: typed user configuration, static `[...slug]` routes, shared post layout, and summary RSS: <https://github.com/satnaing/astro-paper>
- Astro Cactus: centralized site configuration, thin static route, and official Astro RSS integration: <https://github.com/chrismwilliams/astro-theme-cactus>
- Fuwari: grouped TypeScript configuration, article metadata, and typed content routes: <https://github.com/saicaca/fuwari>
- Frosti: explicit user/site configuration and content copyright presentation: <https://github.com/EveSunMaple/Frosti>

## Out Of Scope

Version 0.2.0 does not include npm packaging, search, comments, a CMS, English route generation, Obsidian synchronization, OpenClaw automation, dynamic OG image generation, or automatic conflict-free theme upgrades. Those require separate contracts and can be added after the template release is stable.
