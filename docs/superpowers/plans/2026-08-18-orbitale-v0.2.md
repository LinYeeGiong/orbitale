# Orbitale v0.2.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Release Orbitale v0.2.0 as a reusable GitHub Template with centralized personalization, permanent content pages, working tag archives, summary RSS, MIT licensing, and real documentation screenshots.

**Architecture:** A pure `src/lib/content.ts` module owns URL, sorting, adjacency, and exploration aggregation rules. Astro collection pages adapt entries into that shared model, three thin dynamic routes render one `ArticleLayout`, and `siteConfig` supplies all instance-specific identity to components. The release remains static and framework-free except for Astro and the official RSS package.

**Tech Stack:** Astro 7, TypeScript 6, Astro content collections, `@astrojs/rss`, Vitest, scoped CSS, GitHub Pages

## Global Constraints

- Chinese remains the default locale and only published Chinese entries generate v0.2.0 routes.
- `src/config/site.ts` is the only user-editable personalization entry point.
- Notes, essays, and Daily entries all receive permanent static URLs.
- RSS contains summaries, not rendered article HTML.
- Theme code uses MIT; user-authored content and personal media are excluded from that grant unless separately licensed.
- No UI framework, search, comments, CMS, English routing, Obsidian synchronization, OpenClaw automation, or dynamic OG-image generation is added.
- Every interaction remains keyboard accessible and respects `prefers-reduced-motion`.
- GitHub repository creation, Template activation, push, tag, and Release creation require a separate explicit authorization.

}

import { getCollection, render } from 'astro:content';

export async function getStaticPaths() {
